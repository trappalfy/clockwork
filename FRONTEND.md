## Что за продукт

Clockwork — DEX-агрегатор токенизированных акций на Robinhood Chain. Пользователь подключает кошелёк, меняет ETH на токенизированную акцию (NVDA, AAPL, SPY и ещё около 90) или обратно. Средства всё время остаются у него в кошельке. Ни аккаунтов, ни KYC.

**Тексты описывают только то, что система реально делает.** Оригинал, с которого взята идея, обещает приватную CEX/DEX-агрегацию и скрытые ордера, которых в его коде нет. Мы так не пишем: у нас маршрутизация через публичные пулы Uniswap V3/V4, и говорим мы именно об этом — лучшая цена, расчёт прямо в кошелёк, никакой кастодиальности.

## Стек и жёсткие ограничения

- **Next.js + TypeScript**, App Router, один репозиторий, деплой на Vercel. Tailwind уже подключён.
- **Лендинг** — `app/page.tsx`. 3D на **react-three-fiber** + drei, скролл-анимация на GSAP ScrollTrigger или Lenis.
- Canvas грузится **только на клиенте**: `dynamic(..., { ssr: false })`. Иначе Next.js попробует отрендерить WebGL на сервере и упадёт.
- **3D-зависимости не должны попасть в бандл `/app`.** Лендинг и торговый экран делят только дизайн-токены. Проверяется анализатором бандла.
- **Обязателен облегчённый режим** для `prefers-reduced-motion` и слабых мобильных: сцена заменяется статикой или упрощается. Без этого лендинг съедает батарею и роняет конверсию.
- На странице `/app` — **никаких сторонних скриптов**: ни аналитики, ни виджетов, ни шрифтов с чужих доменов. Там подписывают транзакции.

## Чего фронтенд-агент НЕ трогает

`lib/**`, `app/api/**`, `hooks/**` — зона первого агента (цепочка, котировки, сборка транзакций). Хуки готовы и типизированы, реальные сигнатуры (чуть шире исходного наброска — учитывай их, а не старую версию):

```ts
useWallet()
// { address, isConnected, chainOk, connect, disconnect, switchChain, isSwitching, error }

useMarket()
// { assets: Asset[], ethUsd, isLoading, error }

useQuote({ side, symbol, amount, recipient, slippageBps? })
// { quote: QuoteResponse | null, isLoading, error }
// amount — ETH для buy, количество акций для sell. Дебаунс 450мс встроен, дёргать чаще не нужно.

useSwap()
// { execute(quote), status, approvalStep, txHash, error, reset }
// status: 'idle' | 'approving' | 'signing' | 'pending' | 'success' | 'error'
// approvalStep: { current, total } | null — только во время 'approving', для "Approve 1 из 2"

usePortfolio()
// { ethBalance, positions: Position[], isLoading, error }
```

Все типы экспортируются из `lib/types.ts`. Хуки не рендерят разметку и не содержат стилей.

`Web3Provider` (из `hooks/provider.tsx`) подключён в `app/app/layout.tsx`, не в корневом — это соблюдает требование изоляции бандлов из этого же файла: wagmi и коннекторы не должны попадать в лендинг. Корневой `app/layout.tsx` остаётся только шрифтами и метаданными. Хуки работают везде под `/app`, дополнительно оборачивать ничего не нужно.

Следствие, принятое сознательно: **на лендинге живых данных с цепочки быть не может** — там нет провайдера. Секция `Tape` называет «~90 акций» статическим текстом и остаётся такой. Если однажды понадобятся реальные цены на лендинге, это отдельное решение с возвратом провайдера в корень и потерей изоляции бандла, а не мелкая правка компонента.

Нужны данные, которых нет в этом интерфейсе, — запроси у первого агента, не ходи в цепочку сам.

## Обязательные элементы интерфейса `/app`

- **Адрес получателя виден крупно и всегда**, до подписи. Пользователь подписывает непрозрачный calldata, и адрес назначения — единственное, что он может проверить глазами. Это требование безопасности, а не украшение.
- Понятные состояния: нет суммы, считаем котировку, разрешение (approve) для продажи, ждём подпись, транзакция в сети, успех, ошибка — все берутся напрямую из `useSwap()`'s `status`.
- Проскальзывание и минимум к получению показываются до подписи.
- Предупреждение и кнопка переключения, если кошелёк не в сети 4663.
- Продажа требует отдельного шага разрешения через Permit2 — это два действия подряд, интерфейс должен объяснить пользователю, почему их два.
